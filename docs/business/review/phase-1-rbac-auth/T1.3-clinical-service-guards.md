**Status:** ✅ DONE (static) · **Size:** L · **Priority:** 🔴 P0
**Source:** BUSINESS_FLOW_SOURCE.md §6.1 row 7 ("decorator may be metadata-only, no RolesGuard"),
§6.6 ("DiagnosesController/PrescriptionsController have no @Roles")

## Results (08/07/2026) — full controller sweep

**clinical-emr-service (33 controllers):** all apply `@UseGuards(JwtAuthGuard, RolesGuard)` and a
class-level `@Roles(...)` **except**:
- `appointments.controller.ts` — `JwtAuthGuard` only, **no @Roles** (service-layer actor checks instead — F1-005)
- `patient-representatives.controller.ts` — `JwtAuthGuard` only, no @Roles (F1-008; mitigated: gateway identity + service allowlist `service.ts:248`)
- `files/.../{s3-presigned,s3,local}/files.controller.ts` — `JwtAuthGuard` only, no @Roles (F1-008; verify clinical-file exposure)
- `health.controller.ts` — no guards (OK, public)

`RolesGuard` (`auth/roles/roles.guard.ts`) reads `request.actor.role` (set by JwtAuthGuard from the
**verified** token), and 403s if the role isn't in `@Roles`. Enforcement is real, not metadata. ✅

**Role assignments observed:**
- ADMIN-only: clinics, image-categories, pacs-sync-logs, service-categories, specialties, treatment-rooms
- ADMIN+DOCTOR: clinical-orders, dental-charts, dental-images, diagnoses, diagnostic-orders,
  examination-sessions, image-annotations, lab-test-results, medical-history, medical-records,
  prescription-items, prescriptions, record-exports, symptoms, treatment-history, treatment-plans
- ADMIN+DOCTOR+RECEPTIONIST: doctor-leaves, doctor-schedules, work-shifts
- ADMIN+RECEPTIONIST: doctor-specialties, services
- patients: mixed per-route (ADMIN; ADMIN+DOCTOR+RECEPTIONIST; ADMIN+RECEPTIONIST)

**payment-service:** `payments.controller.ts` — class `@UseGuards(JwtAuthGuard, RolesGuard)` but
per-route overrides: `initiate`/`vnpay-return`/`appointment/:id` open (intended for VNPay IPN +
patient), `refunds`/list/`refund/approve`/`refund/reject` = `@Roles(ADMIN)`, `:id/refund` =
JwtAuthGuard only. ⚠️ Confirm `vnpay-return` verifies VNPay signature (T2.7). Refund **approve** is
ADMIN-only ✅ (matches §K4); refund **initiate** open to any authed user — check business intent.

**iam-service:** accounts/audit-logs/permissions/roles/user-roles/user-profiles/kyc =
`AuthGuard('jwt')` + `@Roles(ADMIN)` (kyc also RECEPTIONIST). **`notifications` /
`notification-templates` / `notification-preferences` = NO guards → F1-001 (🔴).**
`auth-google` / `auth` (login) open = intended.

**NURSE:** appears in **zero** controller `@Roles`. → F1-007.

### Key architectural finding (answers "grant permission to role")
The `@Roles` guard authorizes by **hardcoded role enum**, not by the iam `role-permission` grant
table. The grant model (roles/permissions/user-roles + `role-permission.entity`) exists and Admin
can edit it, but it does not drive backend access control, and login doesn't put permissions in the
JWT. → **F1-003 (🟠).** See T1.5.
