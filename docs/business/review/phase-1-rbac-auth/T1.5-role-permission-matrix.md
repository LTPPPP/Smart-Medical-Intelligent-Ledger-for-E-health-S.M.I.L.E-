## Headline: two RBAC layers, only one is live

| Layer | Exists? | Drives access? |
|-------|:---:|:---:|
| Hardcoded `@Roles(RoleEnum.X)` on controllers | ✅ | ✅ **YES** — this is what actually authorizes |
| iam `role → permission` grant table (`role-permission.entity`, Admin "Role Management" UI, seeds) | ✅ | ❌ **NO** — never read by any guard; not in JWT |

So editing a role's granted permissions in the Admin UI has **no runtime effect**. To make grants
real you'd need: login → resolve permissions from grants → embed in JWT (or fetch per request) →
guards check permission instead of/in addition to role. This is **F1-003** and the biggest
structural decision for the "add permission tag to role" model you asked about.
