# T1.1 — Frontend middleware & route guards

**Status:** ✅ DONE (static) · **Size:** M · **Priority:** 🔴 P0
**Source:** BUSINESS_FLOW_SOURCE.md §6.1 rows 1–5, §11.7 row 1
**Verdict:** 🟢 auth-bypass fixed · ❌ F1-004 (DOCTOR/DENTIST gate) · ❌ F1-006 (presence-only + dead route allowlists)

## Results (08/07/2026)

1. Middleware guard is **active** — `middleware.ts:29-34` redirects unauthenticated users to
   `/login`. `config.matcher:49` excludes only static/image/api/favicon; all app pages covered.
   But it validates **cookie presence only** — no JWT signature/expiry/role check server-side. → F1-006.
2. `PUBLIC_ROUTES` (`routes.ts:113-119`) = home/login/register/forgot/reset only — no clinical
   page leaked. ✅
3. `DOCTOR_ROUTES`/`RECEPTIONIST_ROUTES`/`NURSE_ROUTES` (`routes.ts:132-140`) are **dead code** —
   `grep` finds zero references outside the definition. The doc's "mismatch" is moot because the
   allowlist isn't used at all. → F1-006.
4. Only **3** locations wrap pages in a role/permission guard: `admin/layout.tsx:66`
   (`ProtectedRoute requiredRoles={ADMIN_ROLES}`), `profile/page.tsx`, and the medical-records
   pages (`ProtectedLayout requiredPermissions=['MEDICAL_RECORD_*']`). Every other `(pages)/*`
   route has no route-level role gate — relies on API enforcement. → F1-006 (defense-in-depth gap).
5. `AppNavigation.tsx` is still imported by `ProtectedLayout.tsx:4,23`; it filters items by
   `item.requiredRoles` (`:78-79`) but the sample items have `requiredRoles` commented out
   (`:57`). Live nav is actually `AppShell.tsx` via `resolveDashboardKind`. Low risk; note for cleanup.
6. **F1-004 discovered here:** `CLINICAL_ROLES = ["DENTIST","CLINIC_ADMIN"]` (`roles.ts:31`) and
   `ProtectedRoute` matches `user.roles.includes(role)`. Backend issues role `"DOCTOR"`, so a real
   doctor fails DENTIST-gated checks. `auth.ts:56` maps `roles: data.user.roles ?? [data.user.role...]`
   → user.roles = `["DOCTOR"]`. Mismatch is functional.

**Cookie test (#6 in checklist):** not run — needs running app; the presence-only logic is already
confirmed by code read. Fold into T1.4.

## Current state (pre-scan 08/07/2026)

🟢 Partially fixed already: `middleware.ts` now has an **active** guard — redirects unauthenticated
users to `/login` based on the presence of an `access_token` cookie. But:

- Role-based route protection still depends on client-side `ProtectedRoute` wrapping.
